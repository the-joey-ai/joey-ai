# Evolve mode — growing an existing master

Read the whole file first, then handle what's there in this order.

## 1. The harvest inbox

Take entries one at a time. For each: say what the project learned, then ask where it belongs —

- **Signature** — taste that travels to every platform. The test: would this rule mean the same thing in a web tool and a phone app? "Accent only on text and actions" travels; a Tailwind class does not.
- **Execution notes, under the right platform** — a recipe that only makes sense where it was learned. Concrete values discovered while building ("Geist Sans as the web sans, `tabular-nums` for compared columns") usually land here even when they feel like taste.
- **Nowhere** — a real answer, not a failure. A hack that worked once is not a signature, and absorbing everything is how a master stops meaning anything.

Clear each entry as it's resolved, and restore the section to `_Empty._` when done — an inbox that never empties teaches wrap-session that appending here is a write-only ritual.

## 2. What Joey came with

New rules go straight into the right section, held to the same values-not-vibes standard as the first run — convert any adjective to the observable thing before writing it.

If a new rule contradicts something already there, show both and ask which is current. The contradiction is usually taste having genuinely changed, and the old rule should **go**, not sit alongside — two contradictory rules means every future derivation picks one at random.

## 3. A tightening pass, if the file has grown

Worth doing roughly every few evolve runs, not every time:

- Rules that turned out to be the same rule get merged.
- Rules that never got followed in practice get cut or corrected — check the actual projects if they're in reach; a master that says "no cards" while every project uses cards is documenting an aspiration, and the honest fix is deciding which one is true.
- The Do/Don't table gets any rule that earned its way in from prose above it. The table is what project checklists derive from, so a rule that matters belongs there in checkable form.

A master nobody derives from because it's too long has failed at its only job. When in doubt, cut — the projects it produced still hold the detail.
